## notes

明明还在登录状态、成绩页却报「教务系统暂时不可用（HTTP 901），请稍后重试」的情况修好了：这种回法其实是教务在说登录状态过期，现在认得它，也会去自动续期。
登录状态过期不再把你甩到登录页：提示可以点「稍后」忽略，已经加载好的课表和成绩照样能翻。
学校说「该用户已被禁用」这类原话现在会直接显示给你，不再是一句看不出所以然的英文。
账号被禁用、密码被拒这种重试也不会有用的失败，不再按一分钟一次的频率自动重试（这台教务会累加登录失败次数，反复重试有把账号刷到锁定的风险）；想再试一次可以在设置里手动点。
更新下载改成应用自己下，不再交给系统下载器：失败时给你「重试」和「用浏览器打开」两条出路，下载中也会提醒你先留在本页，退出应用会中断下载。
课表换了材质：周视图卡片和日视图议程用同一套玻璃，课程详情卡会折射底下滚动的网格；长按一节课可以直接设提醒、复制教室或者编辑。
有的学校课表默认入口回「没有访问权限」，现在会自己去菜单里找能用的那个；老千舟把老师班级写在悬浮提示里的格子也能正常显示了。
个别学校把默认参数写在选课函数的声明里，会让提交带错字段，这个一并修掉。
设置 → 编辑学校配置 → 高级 新增「请求最小间隔（毫秒）」：只有你的学校因为短时间重复请求而掉登录时才需要填，比如 600，留 0 表示不限制。

## changelog

本版本的主线是会话失效这条链路：一个状态码判断把「登录已过期」演成了「教务系统暂时不可用」，把三处自愈全部旁路掉。顺带把教务协议层按组与上游做了三方合并，补上登录失败的原文与分级，以及更新下载不再依赖系统下载器。

### 会话失效不再被当成服务器故障（HTTP 901）

正方对带 `X-Requested-With` 的 AJAX 请求报告会话失效时不回 302、也不给登录页 HTML，直接回自定义状态码 **901**。而传输层的判据是 `code == 429 || code >= 500`，`901 >= 500` 命中兜底，于是被判成 `NETWORK_RETRYABLE`，文案正是那句「教务系统暂时不可用（HTTP 901），请稍后重试」。所有以 `SESSION_EXPIRED` 为前提的自愈因此全部落空：成绩页的 `notifyCookieExpired` 不触发，看门狗每 5 分钟重复一次「cookie 正常」的错误结论，`SessionRenewer` 永远醒不来。而 `isLoggedIn` 是纯本地标志，与教务还认不认这个 cookie 无关，所以现象就是"看着登录着，只有重登能救"。

- `AcademicHttpTransport` 赶在 `>= 500` 兜底之前处理 901，常量 `SESSION_EXPIRED_STATUS_CODE` 放在 `AcademicModels`，状态码分类只准发生在传输层这一处（`AcademicRegressionTest` 里有一条专门钉它的测试）。
- **判定按形状收窄，不按码值**：901 同时是非标准码，反向代理和网关都可能回它，而 `SESSION_EXPIRED` 会一路走到 `setLoggedIn(false)`。所以只有「不是登录流程自身的 URL」且「响应不是 HTML」才判过期；不满足形状就把响应原样交回调用方，让页面内容去判，绝不替中间层做主。
- 审查时发现第二处拷贝的映射（`AcademicJson.status()`）有 6 个调用点传的是真实状态码、且全在写请求路径上，会绕开上面这层收窄，已删掉——一处判据只留一份。

### 写请求被甩到登录页时报「会话失效」

选课/退课这类写请求在会话已死时会被教务重定向到登录页，这次写入根本没进后端，原来却报 `RESULT_UNKNOWN`（「结果尚未确认」）——那会让人去核对一份不可能变化的已选列表，而且续期钩子只认 `SESSION_EXPIRED`。现在按 `Location` 认出登录页跳转并报会话失效，其它重定向仍报未知：**绝不跨重定向重放写**。

### 登录失败读教务原文，永久失败不再重试

正方把登录失败原因写在 HTTP 200 响应的 `<p id="tips">` 里，而分类器只在整个响应文本上 `contains` 两个关键词，其余一律 `"Login response could not be verified"`。学校明明说了「该用户已被禁用，请联系管理员」，用户看到的是一句英文。

- 措辞判据抽到 `AcademicHtml`（`loginTip` / `isAccountUnavailableMessage` / `isBadCredentialsMessage`），登录侧与续期侧共用同一份关键词表，不再有两份拷贝。`"Missing csrftoken"` 等用户可见的英文兜底一并翻成中文。
- 账号状态类失败刻意走 `VALIDATION_FAILED` 而不是 `INVALID_CREDENTIALS`：网关把后者映射成一个不带 message 的回调，走那条原文会被丢掉，而静默续期正是靠这段文字认出「永久失败、别再重试」。
- `SessionRecoveryCoordinator` 新增 `RecoveryFailure` 分级，`AccountUnavailable` 与 `CredentialsRejected` 对本会话终止自动重试（`canAttempt` 直接返回 false，看门狗因此走「需要手动登录」那条支路）；用户主动点重试仍放行，换账号或重新登录产生新 token 时记录自动清掉。**刻意不认「过期」两个字**——它会撞上「登录已过期，请重新登录」那类可恢复情况，判成永久失败会把正常静默续期掐掉。
- 设置页提示改成分级文案并带出教务原文（截断 80 字），不再一律「需要重新登录以更新登录状态」。
- 上游在这些地方与我们逐字相同，同样有英文兜底和两份拷贝问题，所以这几条是比上游对。

### 教务协议层按组三方合并上游

上游整层搬不动：它 `academic/` 独有的 12 个文件里有 10 个是从共有文件拆出去的抽取，只搬拆出的文件不搬改过的宿主就是死代码。改成把上游测试当行为规格搬进来（改包名）当探针，红在哪条就说明差在哪，再以我们的文件为底改，不覆盖。25 条探针合掉 15 条，换来 20 条真正可执行的新断言，原有测试 0 回归。

- 千舟旧版课表的 `.kbcontent1` 格子：周次写在格子里、老师班级写在 tooltip 里，用行首节次标签补回来。新增 `QzTimetableCells`。
- 正方个人课表的降级发现：默认入口回「没有访问权限」时去 `initMenu` 找；两个同名入口时保留已配置的菜单身份，绝不瞎猜别的码。新增 `ZfStudySchedule`。
- 表单提交地址：认「先放进紧邻的局部字面量、再赋给 `form.action`」这种写法，但不执行任何学校 JS。分歧按**解析后的端点**判——同一端点写成绝对路径与页面相对路径是常见写法，按字面量比会把今天能用的学校判成「查询地址已变化」；真指向不同地方仍然拒绝猜测，解析不动的候选留在池子里参与判分歧。空 body 加 `authserver` 跳转的页面也认成未登录。
- 选课操作参数：先把字符串字面量和注释按原偏移挖空（`codeMask`）再找 `xsxkOper` 调用点，被注释掉的和塞在生成按钮 HTML 里的调用不再贡献默认值。顺带修掉一个共有的缺陷：解析形参名时没剥掉 JavaScript 默认值，写成 `function xsxkOper(a, b='x')` 的学校会得到 `b='x'` 这样的参数名，选课提交带错字段。
- **刻意没拿的两处**：`qzScheduleForm`（搬来的测试零覆盖）、`classify()` 加固（唯一覆盖它的测试属于编译不过那组）。没有测试撑的上游代码不夹带。千舟 CAS 与 provider 注册表也都不引入。

### 请求最小间隔

正方课表与成绩查询会密集打同一批端点，实测会触发学校的「同一账号多会话」限制——901 很可能就是刚猛刷过成绩/课表之后出现的。自动续期不是免费的：每次重登都产生新会话，而正方按登录失败次数计数、还会升级验证码。所以减少掉登录本身就是目的。

- 移植上游的 `paceRequest` 机制到 `AcademicSessionStore`：按 `Mutex` 串行化，用 `System.nanoTime()` 计时，等待前后各 `requireActive()` 一次，会话被换掉时不会睡完再回来。
- 阈值**不硬编码 host**，走 `SchoolConfig.requestPacingMillis`（默认 0 = 不限制），在 `AcademicHttpTransport` 的重试循环内、`execute` 之前生效。设置 → 编辑学校配置 → 高级 里可填，自用建议值 600。

### 更新下载不再依赖系统下载器

`ACTION_DOWNLOAD_COMPLETE` 这类系统下载器路径在部分 ROM 上会静默失败。改成 OkHttp 自己下：失败给出「重试」与「用浏览器打开」两条出路，下载中提示「请留在本页，退出应用会中断下载」。**代价是失去后台下载与断点续传**——6.4 MB 的包可以接受，包体明显变大时要重新评估这一条。

### 课表材质与长按快捷操作

周视图卡片与日视图议程行改用 `scheduleCardColor` 加渐变亮边和顶部高光，课程详情卡改用 `scheduleDetailGlass` 折射滚动中的网格，长按课程出「设提醒 / 复制教室 / 编辑」菜单。日视图补上焦点登记，详情卡才有共享起点做飞行动画。结构沿用上一版对齐上游的那套，只换材质。日期条的常驻透镜与「重叠课程」选择器刻意没做：前者会碰塌按 `collapse` 测量的日期行，后者超出这次同步范围。

### 验证

- `:app:testDebugUnitTest` 全量 **459 条通过、0 失败、4 跳过**，其中本轮新增 20 条可执行断言（`AcademicRequestPacingTest` 3、`QzTimetableCellsTest` 9、`ZfStudyScheduleTest` 5、`AcademicQueryFormTest` 4、`QzRedirectLoginTest` 2、`QzDynamicOperationTest` 2，以及 `AcademicRegressionTest` 新增 5 条与 `SessionRecoveryCoordinatorTest` 新增 4 条）。`:app:assembleRelease` 通过。
- **真机确认**（正方、密码登录，release 签名包覆盖 v1.2.0 安装）：查课、成绩与考试、课表刷新均正常，登录态与已填的 600ms 间隔在覆盖安装后保留。
- **未确认**：901 现场没能主动复现——在电脑上登录同一账号的教务网页后，app 刷课表和成绩仍然成功。要么该教务不强制单会话，要么后台会话自检抢在手刷之前把 cookie 续上了。所以「过期提示可忽略、不被甩到登录页、静默续期自动恢复」这一段只有单测和设备测试背书，等真实掉线时再观察。另外 legacy 管线在会话失效时仍会把成绩演成「0 门课程」，这条不在本轮范围内。
