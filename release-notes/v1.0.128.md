# App 1.0.128

## notes

- 修复倒计时小组件越过上下课边界后仍未刷新、继续走成负数的问题：边界刷新改用可唤醒的精确闹钟；组件每次重新渲染时，若倒计时目标已经过去就直接显示 00:00，不会把负数画上去。宿主自走的计时器在两次刷新之间由系统推进，如果系统把下一次刷新推迟，桌面可能短暂看到负数，下一次刷新会立即纠正；开机、改时间、改时区、应用升级和账号切换仍会重新计算。开启“大课按小节倒计时”后，小节边界（含课间结束）同样安排边界刷新。
- 小组件上下课边界刷新改用可短暂唤醒设备的精确闹钟，每天只在上课、下课等少量边界触发，避免休眠或省电策略把刷新压到很久以后。没有精确闹钟权限时退回系统普通闹钟，由 30 分钟弹性后台任务兜底。`docs/schedule/BACKGROUND-REMINDERS.md` 已同步说明。
- 倒计时小组件新增“大课按小节倒计时”选项（每个倒计时组件独立设置，默认关闭）：按每小节下课时间倒计时，课中显示“距课间”，课间显示“课间休息 · 距上课”，只有最后一节结束才显示“距下课”；进度条按剩余时间从满格走到 0，课间隐藏；节次时间缺失、区间异常或该次课被调课时回退为整门课倒计时。课间文案在窄组件上完整显示，不再被倒计时容器挤成省略号。
- 每种小组件的外观设置新增“今日课后显示明日课表”选项（每个组件独立设置，默认关闭）：今日课程全部结束（含今天本来没课）后显示“今日课程结束”并列出明日课程；明日无课显示“明日无课”。单课/双课显示明日前两节，时间轴列出明日全部课程，倒计时样式显示明日第一节并倒计时到“距明日上课”。
- 未打开这两个选项的已有组件行为不变。

## verification

本次小组件相关 JVM 单测（Robolectric，API 24/33）通过：schedule 包 274 项测试全部通过，覆盖“目标已过期时渲染 00:00、不会把负数画上去”的静态兜底、按小节/课间分段倒计时与后续节次缺失/倒序回退、小节边界刷新时间、进度条从满格走向 0、课间文案不被省略、明日在 130×130dp 大字体下不裁切、可唤醒边界闹钟、外观开关的读写与默认关闭，以及“隔离宿主 ClassLoader 下四个小组件布局仍可 inflate”的桌面进程兼容回归（防止布局再次引用 app 自定义 View）。真机验证：1.0.128 dev 包已在 vivo V2229A 上验证过 10:50 小节边界自动刷新为“课间休息 · 距上课”、课间文案完整、计时为正；撤销自定义倒计时控件后本轮未重新装机复验（设备已断开）。未在 MuMu 或最终签名包上验证，厂商后台限制与真实桌面刷新时机仍待发布验收。本机完整单测仍有 46 个与本轮改动无关的 crypto/SSO 用例失败，这些失败在干净 HEAD 上同样复现（属本机环境问题），因此这里不声明“全量单测通过”。
