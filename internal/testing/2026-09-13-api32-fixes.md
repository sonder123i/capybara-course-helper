# API 32 交互、折射与课表修正验证

验证日期：2026-09-13。基于 `main` 的 `38b4fd3`，合入 `main` 与 `v2`，发布目标为 `v1.0.76`。本记录陈述本地验证；CI/CD 的构建、发布和 Gitee 同步结果以远端流水线为准。

## 本轮修正

| 区域 | 最终行为 |
| --- | --- |
| 底栏、分段栏、数值及颜色滑块 | 拖动期间直接采用指针位置和事件时间戳，不再每次移动都启动位置弹簧与速度弹簧。点击和松手继续使用弹簧，并继承当前画面的位置、速度；反向拖动立即跟随。底栏拖回原标签也会准确归位。 |
| 分段栏弹性 | 按最后一次“稍微少一点”的反馈，只收敛分段控件：切换阻尼 / 刚度 `0.60 / 400`，松手 `0.62 / 480`，按压 `0.64 / 680`；按压缩放由 `1.10` 调为 `1.08`，速度拉伸上限由 `0.16` 调为 `0.13`。 |
| 课程图标 | Books 的复合路径在每次闭合后使用绝对轮廓起点，避免 Android 12 将相对起点连接成向下的三角形。保留原 Phosphor 图形、双色分层与动画。 |
| 底栏玻璃中的图标 | 静态模糊底图与动画图标分别缓存；滚动只刷新背景，图标动画只刷新前景，两张已有快照在 CPU 合成，避免额外 GPU 回读。隐藏图层完成录制后再发布更新，修复图标已停止但折射层仍显示上一帧填充的问题。 |
| 开始按钮及圆弧菜单 | 闭合时仅采样按钮周围 `112×112dp`；展开时扩大到覆盖菜单和 `24dp` 边距的区域，避免反复采集整页。入场与背景模糊变化期间限频更新，终点立即补拍。按钮维持 `64dp` 和现有长按行为。 |
| API 31/32 折射 | 按实测四角处理非对称轮廓，允许圆弧菜单的大圆角超过半短边；普通圆形、胶囊形仍用简洁的对称计算。着色器、裁剪及首帧回退共用形状。按当前坐标换算祖先变换和控件自身形变，修正采样偏移。没有色散时只采样一次。 |
| 大菜单计算量 | 仅圆弧菜单的模糊光学底层限制为最多 `160,000` 个离屏像素，保持原逻辑采样坐标；按钮、图标、文字和外轮廓仍按原分辨率绘制。已交给 Compose 的结果位图不再被后续帧改写或回收，回读缓冲继续复用。 |
| API 33+ 玻璃 | 将 `lens()` 的色散参数改成具名传参。此前第三个位置参数实际开启的是 `depthEffect`，现在准确传入 `chromaticAberration`。 |
| 课表顶栏 | 按实际父容器宽度和文字测量结果排列，放得下时保持左侧周次 / 学期、右侧四个操作；窄屏与大字再换行。星期与课程列共用时间列阴影宽度。 |
| 长教室名 | 取消教室两行省略，根据真实排版宽度测量并增加统一节次行高，使时间轴、网格和课程跨度一致。状态图标移到地点下方。 |
| 课程详情 | 卡片展开从 `40ms` 延迟加 `460ms` 改为立即开始、`220ms` 完成，内容分组在 `240ms` 内完成。保留从课程卡片展开、拖动关闭、返回取消、主题切换、删除撤销和焦点恢复。 |

没有增加持久化字段，也没有修改教务请求协议。玻璃关闭、减少动态效果及高对比度策略沿用现有实现。

## 性能证据与限制

像素预算、缩小采样区域和静态底图复用均有设备断言，能确认执行了这些优化。功能通过和较少像素并不能单独证明实际帧耗时改善。

前三次开始按钮测量时，主机负载波动明显，最繁忙时 20 个逻辑处理器合计负载为 100%。三轮真实按压与开关菜单的合并帧中位数 / p95 分别为：原版本 `8.7 / 36.4ms`，修正坐标与刷新后 `11.7 / 57.0ms`，加入像素预算但主机满载时 `31.8 / 119.4ms`。最后一组有约 `2.6s` 的极端帧，不能据此给出性能提升比例。

构建结束后重新对照旧预览包，随后减少底栏重复回读并恢复对称轮廓的简洁计算。旧包与最终代码均使用相同的 `MainPerformanceDeviceTest`，每种场景测量三轮；两项诊断测试通过。合并全部帧的结果如下，单位为毫秒：

| 场景 | 旧包中位数 / p95 | 最终代码中位数 / p95 |
| --- | --- | --- |
| 开始按钮按压及开关菜单 | 6.09 / 36.14 | 6.90 / 36.59 |
| 重复切页 | 47.67 / 135.87 | 59.25 / 170.69 |
| 课表滚动 | 17.87 / 34.57 | 17.97 / 72.09 |
| 成绩滚动 | 17.88 / 107.02 | 17.87 / 119.69 |

两版三轮静置均为零重绘、零重组。最终代码的重复切页和部分滚动慢帧仍高于旧包，**尚未证明整体帧率改善，也不能宣称卡顿完全解决**。本轮确认的是拖动位置不再追赶弹簧、折射几何正确、采样面积减少及不变图层复用。模拟器与主机负载会影响耗时；后续仍需继续排查慢帧。

原始日志为 `performance-control-old-32.txt`、`performance-optimized-32.txt`，原始 JSON 在 `final-performance-32/performance-validation/`；汇总为 `final-performance-summary.json`，对照包校验值见 `performance-apk-hashes.json`。
